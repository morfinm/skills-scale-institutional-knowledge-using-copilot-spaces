# OctoAcme Project Management Docs

This README provides a central entry point for OctoAcme's project management process documentation and a brief overview of how the team operates.

## Purpose
These documents capture the standard project management practices used by OctoAcme so the team can work consistently, communicate clearly, and onboard quickly.

## Project management process summary
OctoAcme follows a lightweight, iterative lifecycle designed to turn ideas into delivery-ready work with visibility across stakeholders and teams.

- Initiation: validate the problem, align stakeholders, define goals, success metrics, and milestones.
- Planning: create a prioritized backlog, estimate scope, identify dependencies and risks, and define the Definition of Done.
- Execution: deliver in small increments with standups, reviews, and continuous tracking against milestones.
- Risk and communication: manage blockers, escalate issues appropriately, and keep stakeholders informed.
- Release and deployment: validate readiness, deploy with checks, and communicate outcomes.
- Retrospective and improvement: capture learnings and convert them into actionable follow-up work.

## Core roles
- Project Manager (PM): coordinates delivery, schedules, risks, and communication.
- Product Manager (PdM): defines outcomes, prioritizes the backlog, and measures success.
- Developers: implement features, write and maintain tests, and review quality.
- QA/Testing: validate acceptance criteria and release readiness.
- Stakeholders: provide input, priority, and approvals.

## How to use this documentation set
- Start with the Project Management Overview for a high-level understanding.
- Use the initiation and planning guides to prepare a new effort.
- Reference execution, communication, and release docs during delivery.
- Record learnings and improvement actions in the retrospective guidance.

## Documentation standards
- Keep project artifacts current in the repo.
- Use lightweight, repeatable checklists for delivery and release.
- Make risks, dependencies, and milestones visible to the team.
- Tie decisions and actions back to measurable outcomes.
